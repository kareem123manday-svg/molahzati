# ملاحظاتي

تطبيق ملاحظات عربي كامل بواجهة RTL احترافية، يعمل في المتصفح ويتزامن مع قاعدة بيانات **Supabase** سحابية. يمكن لكل مستخدم إنشاء حساب وتسجيل الدخول من أي جهاز، ولا يصل إلى ملاحظات غيره بفضل سياسات عزل الصفوف (Row Level Security).

**النسخة المباشرة:** https://kareem123manday-svg.github.io/molahzati/

## التشغيل

من داخل مجلد المشروع:

```bash
node server.js
```

ثم افتح:

```text
http://localhost:3000
```

يمكن تغيير المنفذ عبر متغير `PORT`، مثل `PORT=8080 node server.js` على Linux/macOS أو `$env:PORT=8080; node server.js` في PowerShell.

> يفضَّل استخدام Chrome أو Edge أو Firefox أو Safari بإصدار حديث. لا توجد أدوات بناء أو تثبيت حزم للتطبيق نفسه.

## إعداد Supabase لأول مرة

المشروع يحتاج إلى تطبيق مخطط قاعدة البيانات مرة واحدة فقط:

1. افتح لوحة مشروع Supabase.
2. انتقل إلى **SQL Editor** ثم **New query**.
3. انسخ محتوى الملف [`supabase-schema.sql`](supabase-schema.sql) والصقه، ثم اضغط **Run**.
4. من **Authentication → URL Configuration** أضف عنوان التطبيق إلى **Site URL** و**Redirect URLs**، مثل:
   - `https://kareem123manday-svg.github.io/molahzati/`
   - `http://localhost:3000`
   - عنوان النشر الفعلي عند رفعه.
5. تأكد من أن تسجيل الدخول بالبريد وكلمة المرور مفعّل من **Authentication → Providers → Email**.

إذا كان تأكيد البريد الإلكتروني مفعّلًا، فسيصل رابط تأكيد إلى بريد المستخدم قبل أول تسجيل دخول. يمكن تعطيله من إعدادات البريد في Supabase إن رغبت.

### إعدادات الواجهة

يحتوي [`supabase-config.js`](supabase-config.js) على:

- رابط المشروع.
- المفتاح العام **Publishable**، وهو مصمم للاستخدام في المتصفح.

لا تضع أبدًا المفتاح السري **Secret** أو **Service Role** في `supabase-config.js` أو `app.js` أو أي ملف يُنشر للواجهة. المفتاح السري يتجاوز سياسات RLS، ويجب أن يبقى على الخادم فقط. إذا تسرّب أي مفتاح سري، فأبطله وأنشئ مفتاحًا جديدًا من لوحة Supabase.

## المزايا

- إنشاء حساب بالبريد الإلكتروني وكلمة المرور عبر Supabase Auth.
- عزل كامل لبيانات كل مستخدم عبر سياسات RLS.
- مزامنة الملاحظات بين الأجهزة والمتصفحات بعد تسجيل الدخول.
- إنشاء الملاحظات وتعديلها وحذفها، مع حفظ تلقائي داخل المحرر.
- تثبيت الملاحظات، وإضافتها إلى المفضلة، وأرشفتها.
- سلة مهملات مع استعادة، وحذف نهائي بعد تأكيد، وتنظيف تلقائي بعد 30 يومًا عند فتح التطبيق.
- وسوم ملوّنة وألوان للملاحظات.
- بحث عربي يتجاهل التشكيل وفروق الهمزات والتاء المربوطة.
- ترتيب حسب آخر تحديث أو تاريخ الإنشاء أو العنوان، وعرض شبكي أو قائمة.
- إعدادات الحساب، وتغيير كلمة المرور.
- تصدير نسخة احتياطية بصيغة JSON.
- حذف الحساب وكل بياناته نهائيًا بعد تأكيد كلمة المرور.
- ثيمات فاتح وداكن وحسب النظام، وتصميم متجاوب للجوال.
- اختصارات لوحة المفاتيح: `N` لملاحظة جديدة، `Ctrl/Cmd + K` أو `/` للبحث، `Ctrl/Cmd + S` للحفظ، و`Esc` للإغلاق.

## البنية

```text
server.js           خادم محلي بسيط بدون اعتماديات
index.html          هيكل الواجهة العربية
styles.css          نظام التصميم والثيمات والتجاوب
app.js              المنطق والمصادقة وإدارة الملاحظات عبر Supabase
supabase-config.js  رابط المشروع والمفتاح العام فقط
supabase-schema.sql مخطط الجداول والسياسات والدوال
favicon.svg         أيقونة الموقع
```

جميع الملفات مطلوبة للتشغيل، ويُنفَّذ مخطط SQL مرة واحدة من لوحة Supabase.

## نموذج البيانات

### `profiles`

| العمود | النوع | الوصف |
| --- | --- | --- |
| `id` | `uuid` | معرّف المستخدم، مرتبط بـ `auth.users` |
| `name` | `text` | الاسم المعروض |
| `hue` | `integer` | درجة لون الصورة الرمزية |
| `welcome_seeded` | `boolean` | هل أُنشئت ملاحظة الترحيب؟ |
| `created_at` | `timestamptz` | تاريخ الانضمام |
| `updated_at` | `timestamptz` | آخر تحديث |

### `notes`

| العمود | النوع | الوصف |
| --- | --- | --- |
| `id` | `uuid` | معرّف الملاحظة |
| `user_id` | `uuid` | صاحب الملاحظة |
| `title` | `text` | العنوان |
| `content` | `text` | النص |
| `tags` | `text[]` | الوسوم |
| `color` | `text` | لون الملاحظة |
| `pinned`, `favorite`, `archived`, `trashed` | `boolean` | حالات الملاحظة |
| `trashed_at` | `timestamptz` | تاريخ النقل إلى السلة |
| `created_at`, `updated_at` | `timestamptz` | التواريخ |

جميع الجداول محمية بـ RLS، ولا توجد سياسة تسمح بالوصول إلى صفوف مستخدم آخر.

## الأمان وحدوده

- المصادقة تتم عبر Supabase Auth، ولا يخزّن التطبيق كلمات المرور.
- كل طلب إلى قاعدة البيانات يمر عبر جلسة المستخدم، وسياسات RLS تمنع قراءة أو تعديل أو حذف ملاحظات الآخرين.
- الاتصال مشفّر عبر HTTPS/TLS، وبيانات Supabase مشفّرة عند التخزين وفق إعدادات المنصة.
- حذف الحساب يتم عبر دالة `delete_own_account()` آمنة، وتتحقق من هوية المستخدم الحالي فقط.
- المفتاح العام الموجود في الواجهة آمن للنشر؛ المفتاح السري غير موجود في المشروع.
- التطبيق لا يوفّر تشفيرًا من طرف إلى طرف (E2E)؛ مدير مشروع Supabase يملك صلاحية إدارية على قاعدة البيانات. إذا كان مطلوبًا نموذج E2E حقيقي، فيجب إضافة طبقة تشفير بمفتاح يحتفظ به المستخدم ولا يُرسل إلى الخادم.

قيود يجب معرفتها:

- التطبيق يحتاج إلى اتصال بالإنترنت لتحميل الملاحظات وحفظها؛ لا يوجد وضع عمل دون اتصال.
- الملف المصدَّر بصيغة JSON غير مشفّر، لذا احفظه في مكان آمن.
- لا توجد مزامنة لحظية بين التبويبات المفتوحة في الوقت نفسه؛ تُحدَّث البيانات عند إعادة تحميل الصفحة أو تنفيذ إجراء جديد.
- لا توجد واجهة لاستعادة كلمة المرور حتى الآن؛ يمكن إضافتها لاحقًا باستخدام Supabase Auth.
- لا تُرحَّل بيانات النسخة المحلية القديمة تلقائيًا إلى السحابة؛ يبدأ كل حساب Supabase بملاحظاته الخاصة.
- تُحفظ تفضيلات الواجهة فقط (الثيم، طريقة العرض، الترتيب، آخر بريد) في `localStorage`؛ أما الحساب والملاحظات فكلها في Supabase.
- الخط العربي يُحمَّل من Google Fonts عند توفر الاتصال، مع بدائل نظامية عند تعذره.

## ملاحظة

لا يستخدم التطبيق أي أدوات تتبّع. الاتصالات الخارجية الأساسية هي Supabase وGoogle Fonts فقط.
